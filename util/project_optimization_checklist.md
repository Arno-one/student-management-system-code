## 3.3 收紧生产安全默认配置

**优先级：P0**

### 当前信号

- CORS 目前是全开放，`main.py:55-61`
- 全局 500 错误直接把异常字符串回给前端，`main.py:103-115`
- 鉴权密钥有默认兜底值 `change-me-in-env`，`config.py:54-55`
- 前端 token 存在 `localStorage`，`frontend-vue/src/api/index.js:14-18,29-35`

5. 重新评估 token 存储策略与 XSS 风险

### 价值

- 更适合对外展示或多人使用
- 能减少敏感信息泄漏风险
- 是把项目从“课程/演示级”走向“可部署级”的关键一步

### 重点参考位置

- `main.py:55-61`

## 3.4 补齐依赖锁定与环境校验

## 3.5 收敛重复的序列化与查询编排逻辑

**优先级：P1**

### 当前信号

- `auth_service` 里同时承担了查询拼装、序列化、列表组装等多种职责，`service/auth_service.py:22-72,143-163,221-239`

- 提高 locality，后续改字段/改返回结构更集中
- 减少重复代码
- 对系统管理模块扩展最有帮助

### 重点参考位置

- `service/auth_service.py:22-72`
- `service/auth_service.py:143-163`

## 5. 我个人的推荐顺序

如果让我帮你排一个最合理顺序，我建议是：

1. **先做方案 A：基础质量包**
2. **再做方案 B：生产可用包**
3. **最后做方案 C：AI 深化包**
4. 产品增强类（P2）按你展示需求选择

原因很简单：

- 没有测试和迁移，后面任何重构都容易变危险
- 没有安全和运维收口，AI 能力越多，问题越多
- 基础稳住之后，再继续深化 Dify / NL2SQL，收益最大
