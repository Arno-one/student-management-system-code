# 多轮记忆对话功能实现文档

## 一、功能简介

调用 DeepSeek 大模型实现「多轮记忆对话」：在同一段会话中，模型能够"记住"之前聊过的内容，从而进行连续、有上下文的对话。

例如：

| 轮次 | 用户输入 | 模型回复 |
| --- | --- | --- |
| 第 1 轮 | 我叫小明 | 你好小明，有什么可以帮你的？ |
| 第 2 轮 | 我叫什么名字？ | 你叫小明。 |

第 2 轮之所以能答对，正是因为模型带上了第 1 轮的上下文。

---

## 二、核心实现思路

### 1. 为什么需要"自己存历史"

HTTP 接口本身是**无状态**的——每次请求之间互不相关，模型默认不会知道你上一次说了什么。

所以要实现"记忆"，关键在于：**自己把历史消息保存起来，每次对话都把完整的历史一起发给模型。**

### 2. 如何区分不同的对话

引入一个 `session_id`（会话标识）来区分不同对话，原理就像微信里不同的聊天窗口互不干扰：

- 同一个 `session_id` 的多次请求 = 同一段连续对话，共享历史上下文。
- 不同的 `session_id` = 各自独立的对话，互不影响。

`session_id` 由前端自己生成并保持（比如用用户 ID，或一个唯一字符串）。

### 3. 记忆的存储结构

用一个全局字典 `conversation_store` 在内存中保存历史：

- **key**：`session_id`（会话标识）
- **value**：该会话的消息列表 `messages`

每条消息的格式遵循 OpenAI 规范：

```python
{"role": "system",    "content": "人设/系统设定"}   # 设定模型角色，每个会话开头一条
{"role": "user",      "content": "用户说的话"}        # 用户输入
{"role": "assistant", "content": "模型的回复"}        # 模型回复
```

### 4. 一轮对话的完整流程

```
用户发来 (session_id, prompt)
        │
        ▼
是新会话？  ── 是 ──► 初始化一条 system 人设消息
        │
        ▼
把 user 这轮输入追加到该会话的历史 messages
        │
        ▼
把"完整历史 messages"一起发给 DeepSeek（模型据此实现记忆）
        │
        ▼
拿到模型回复 reply
        │
        ▼
把 assistant 回复也追加进历史（作为下一轮的上下文）
        │
        ▼
返回 reply 给前端
```

## 三、具体代码

### 1. Service 层：`service/work_service.py`

负责对话的核心逻辑与历史存储。

```python
# ============ 多轮记忆对话相关 ============
# 用一个全局字典在内存中保存每个会话的历史消息
# key 是 session_id（会话标识），value 是这个会话的消息列表
# 注意：存在内存里，服务一重启就清空；生产环境建议换成 Redis 等持久化存储
conversation_store: dict[str, list[dict]] = {}


def talks(session_id: str, prompt: str):
    """
    多轮记忆对话：根据 session_id 区分不同的对话，自动带上历史上下文调用 deepseek
    :param session_id: 会话标识，同一个标识就是同一段连续对话
    :param prompt: 用户这一轮说的话
    :return: 大模型这一轮的回复内容
    """
    # 如果是新会话，先初始化一条 system 消息，设定大模型的人设
    if session_id not in conversation_store:
        conversation_store[session_id] = [
            {"role": "system", "content": "你是一个经验丰富的工作助手，会帮助我完成一些任务"},
        ]

    # 取出这个会话的历史消息，并把用户这一轮的输入追加进去
    messages = conversation_store[session_id]
    messages.append({"role": "user", "content": prompt})

    # 把完整的历史消息（含上下文）一起发给 deepseek，模型据此实现"记忆"
    response = client.chat.completions.create(
        model="deepseek-v4-flash",
        messages=messages,
        stream=False,  # 是否流式返回
        reasoning_effort="high",  # 思考强度
        extra_body={"thinking": {"type": "enabled"}}  # 是否思考
    )

    # 拿到模型回复，并把回复也存进历史，作为下一轮对话的上下文
    reply = response.choices[0].message.content
    messages.append({"role": "assistant", "content": reply})

    return reply


def clear_talks(session_id: str):
    """
    清空指定会话的历史记忆，相当于重新开始一段全新对话
    :param session_id: 要清空的会话标识
    :return: 操作结果
    """
    if session_id in conversation_store:
        del conversation_store[session_id]
        return {"success": True, "message": f"会话 {session_id} 的记忆已清空"}
    return {"success": False, "message": f"未找到会话 {session_id}"}
```

> 说明：`client` 为文件顶部已初始化好的 DeepSeek 客户端：
>
> ```python
> from openai import OpenAI
> client = OpenAI(
>     api_key='sk-xxxxxx',
>     base_url="https://api.deepseek.com")
> ```

### 2. API 层：`API/work_api.py`

对外暴露 HTTP 接口。

```python
@woker.post("/talks", summary="多轮记忆对话")
def talks(session_id: str, prompt: str):
    """
    多轮记忆对话接口：同一个 session_id 下的多次请求会带上历史上下文，实现连续对话
    :param session_id: 会话标识，前端自己生成（比如用户ID或一个唯一串），同一会话保持不变
    :param prompt: 用户这一轮输入的内容
    :return: 大模型这一轮的回复
    """
    reply = work_service.talks(session_id, prompt)
    return {"session_id": session_id, "reply": reply}


@woker.post("/talks/clear", summary="清空指定会话的对话记忆")
def clear_talks(session_id: str):
    """
    清空某个会话的历史记忆，下次对话就是全新开始
    :param session_id: 要清空的会话标识
    """
    return work_service.clear_talks(session_id)
```

## 四、接口说明

### 1. 多轮对话

- **URL**：`POST /talks`
- **参数**：

| 参数名 | 类型 | 说明 |
| --- | --- | --- |
| session_id | string | 会话标识，同一会话保持不变 |
| prompt | string | 用户这一轮的输入 |

- **返回示例**：

```json
{
  "session_id": "user_1001",
  "reply": "你好小明，有什么可以帮你的？"
}
```

### 2. 清空会话记忆

- **URL**：`POST /talks/clear`
- **参数**：

| 参数名 | 类型 | 说明 |
| --- | --- | --- |
| session_id | string | 要清空记忆的会话标识 |

- **返回示例**：

```json
{
  "success": true,
  "message": "会话 user_1001 的记忆已清空"
}
```

## 五、调用示例

```bash
# 第一轮：告诉模型我的名字
POST /talks?session_id=user_1001&prompt=我叫小明

# 第二轮：测试记忆，模型应回答"小明"
POST /talks?session_id=user_1001&prompt=我叫什么名字？

# 不想聊了，清空记忆重新开始
POST /talks/clear?session_id=user_1001
```

## 六、注意事项与可优化点

1. **记忆存在内存里，服务重启即丢失**
   当前用全局字典存储，重启服务历史会清空。若需长期保存，建议改用 Redis / 数据库等持久化存储。

2. **历史会越来越长，token 消耗增加**
   随着对话轮数增加，发送给模型的历史越来越长，不仅费用上升，还可能超出模型上下文长度限制。
   可优化为「只保留最近 N 轮对话」或对早期历史做摘要压缩。

3. **多用户并发**
   不同用户务必使用不同的 `session_id`，否则会串台（共享同一段记忆）。
