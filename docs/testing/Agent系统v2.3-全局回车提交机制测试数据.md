# Agent 系统 v2.3 - 全局回车提交机制测试数据

## 需求目标

为系统内常规业务输入区补充统一的回车提交机制，减少鼠标点击成本。

目标体验：

- 在普通输入框中按 `Enter`，直接触发当前操作区的默认提交按钮。
- 在普通业务文本域中按 `Enter`，直接提交；按 `Shift + Enter` 保留换行能力。
- 聊天、富文本、反馈说明等特殊文本域保留原有交互，不被全局回车机制误伤。

## 设计说明

本次实现采用前端全局监听方案，在 `App.vue` 启动时初始化一次，统一接管回车提交行为。

核心规则：

1. 仅处理常规 `input` 和允许提交的 `textarea`。
2. 跳过以下特殊区域：
   - Agent 主对话输入区
   - FloatingAgent 对话输入区
   - RAG 问答输入区
   - 富文本邮件正文编辑区
   - 反馈原因填写区
   - HITL 正文长文本区
3. 不处理带修饰键的回车：
   - `Shift + Enter`
   - `Ctrl + Enter`
   - `Meta + Enter`
   - `Alt + Enter`
4. 不再全局扫描整个卡片里的“主按钮”，而是优先定位离当前输入框最近的一组操作区，再在该组里选择默认按钮，避免串到后面的别的功能按钮。

## 关键回归场景

### 场景 1：系统管理查询用户

前置条件：

- 管理员已登录
- 进入系统管理 `sys-users`

操作：

1. 在“查询用户”的账号输入框中输入 `admin`
2. 按 `Enter`

预期：

- 触发当前“查询用户”操作区的查询按钮
- 发起 `/system/users` 查询请求
- 不会串到下方“新增用户”按钮

### 场景 2：多按钮卡片默认命中当前操作区

适用页面：

- 学生管理
- 成绩管理
- 系统管理

预期：

- 在“查询”区输入后按回车，只触发查询按钮
- 在“新增”区输入后按回车，只触发新增按钮
- 在“更新/删除”区输入后按回车，只触发当前区的默认主按钮

### 场景 3：特殊文本域不误触发

适用页面：

- Agent 对话
- FloatingAgent
- RAG 问答
- 邮件富文本正文
- 反馈原因填写

预期：

- 普通 `Enter` 不被全局提交逻辑接管
- 保留原页面既有的发送或换行规则
